# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this is

Two Tkinter desktop apps sharing one storage layer:

- `AI_Journal_App.py` — a day-by-day journal with a Gemini "AI reflection", text-to-speech playback (gTTS + pygame) and microphone dictation (SpeechRecognition).
- `AI_Companion_App.py` — a conversation with one character you define, whose mood, closeness and current desire shift as you talk.
- `core.py` — the data directory, atomic writes, key derivation and encrypted read/write that both apps use. Deliberately free of Tkinter so it can be tested without a display.
- `library.py` — the companion's reading: text extraction from .txt/.md/.pdf/.docx/.epub, splitting into passages, and BM25 search. Also Tkinter-free.

There is no package and no build system; each app is run directly. The two apps keep separate data directories and separate passwords — they share code, not state.

## Commands

```bash
# Run
python AI_Journal_App.py
python AI_Companion_App.py

# Tests — they drive the real windows, so they need a display
xvfb-run -a python3 tests/test_journal.py
xvfb-run -a python3 tests/test_companion.py
cd tests && python3 test_library.py   # no display needed

# Dependencies — use "python -m pip", not bare "pip", so they land in the Python that runs the app
python -m pip install -r requirements.txt
python install.py                    # same thing, for people who run .py files by double-click
python -m pip install pyaudio        # optional: only dictation / voice mode need it
```

`install.py` exists because "pip says it installed, the app still says No module named …" is the usual first-run failure on Windows, where several Pythons coexist: it installs through `sys.executable`, so whichever Python opens it is the one that gets the packages. Its `PACKAGES` list must stay in step with `requirements.txt`. It waits for Enter before closing, since a double-clicked console window otherwise vanishes before the result can be read.

PyAudio is deliberately left out of `requirements.txt`: where no prebuilt wheel exists for the user's Python it fails to compile, and one failure aborts the whole `-r` install. Nothing imports it at startup — `speech_recognition` only loads it when a `Microphone()` is opened — so the apps run without it and dictation reports the error through `set_status`.

`google-generativeai` is end-of-life (it prints a `FutureWarning` on import saying so; the replacement is `google-genai`). It still installs and works, but it is the first thing to suspect if Gemini calls start failing.

Both apps `import core`, and the companion also `import library`, so they must sit next to those files. Copying a single app file somewhere else on its own fails at startup with `No module named 'core'`.

Optional dependencies (`edge_tts`, and `pypdf` inside `library.py`) are imported under `except Exception`, not `except ImportError`: a package that is present but broken — or that trips over another package on import, as pypdf does over a Pillow without `__version__` — must cost only its own feature, never the app's startup.

`resource_path()` reads `sys._MEIPASS`, so the app is meant to be frozen with PyInstaller and `cover.png` bundled as data (`--add-data`). The image is optional at runtime — the cover screen falls back to a plain dark canvas when it is missing.

## Architecture

**One class, two screens, one window.** `AIJournalHardcoded` builds both `self.main_frame` (the journal) and `self.cover_frame` (the lock/cover screen) against the same `root`. Only the cover is packed at startup; `open_journal`/`verify_password` destroy the cover and pack the main frame, `return_to_cover` does the reverse and *rebuilds* the cover from scratch. Anything added to the cover must therefore be re-created in `build_cover_screen()`, not stashed on the instance.

The window is borderless (`overrideredirect(True)`, `-topmost`), so there is no OS title bar: dragging is implemented manually with `get_pos`/`move_window` bound on the canvas and the top bar, and the `dragged` flag exists so that a drag-release does not count as the "click anywhere to open" gesture.

**The password encrypts the journal — it is not just a screen gate.** `derive_key()` runs PBKDF2-HMAC-SHA256 (480k iterations) over the password and a per-config salt to produce a Fernet key. `config.json` stores the salt and a `password_check` token (a Fernet-encrypted constant), so `verify_password` proves the password by decrypting that token rather than by comparing strings. The plaintext password lives only in `self.user_password` while unlocked, so Settings can prefill it; `return_to_cover` drops the key, the password and the decrypted `journal_data`. A locked app refuses to save at all — writing without the key would replace the ciphertext with plaintext. `apply_password_change()` re-keys the file in place and rolls back if the rewrite fails, and `migrate_legacy_password()` converts a plaintext `password` from an older config on startup. There is no recovery path: a forgotten password means unreadable history.

**Widgets are the model.** There is no in-memory state object for a day. `save_current_day_data()` reconstructs the day by reading widget properties — water intake is counted by comparing each label's text to `"●"`, mood is the emoji string in `self.current_mood`, to-dos come from the `Entry`/`BooleanVar` pairs in `self.todo_items`. Changing a glyph or a widget type means changing the persistence code with it. Each to-do row carries its own `✕` that removes that row (`remove_todo_item(item)` takes the item, not the last one), and a ticked task is restyled through `style_todo_item()` with the shared `todo_font_done` (overstrike) — the two `tkfont.Font` objects are built once in `__init__`, so per-row fonts must not be constructed ad hoc. `MAX_TODO_ITEMS` is reported through `set_status` rather than failing silently.

**Persistence.** Two JSON files in a per-user data directory — `user_data_dir()` resolves to `%APPDATA%\AI_Journal`, `~/Library/Application Support/AI_Journal` or `$XDG_CONFIG_HOME/AI_Journal`, and falls back to the working directory if that cannot be created. `migrate_legacy_files()` copies files an older version left in the working directory on first run. Both files are written by `write_json_atomic()` (temp file + `os.replace` + `fsync`), so a failed write cannot truncate the existing one, and the failure is shown in `self.status_lbl` in the top bar rather than swallowed. If `journal_history.json` fails to parse, `history_load_failed` is set and `save_current_day_data` refuses to write at all — an unreadable history is never clobbered by an empty one.
- `config.json` — `api_key`, `user_name`, `password_salt`, `password_check`. The password itself is never written to disk. Read as utf-8 with a locale-encoding fallback for files written by older versions. The API key is still plaintext here.
- `journal_history.json` — either the plain day map, or `{"encrypted": true, "payload": <Fernet token>}` when a password is set. `write_history()` picks the form from whether `self.fernet` exists; `load_journal_data()` returns `{}` (not a failure) for an encrypted file read before unlocking. Plain form: one entry per day, keyed by `"{year}-{MON}-{day}"` with a short uppercase month and an unpadded day (e.g. `2026-AUG-25`). Keys sort lexically, not chronologically; `analyze_journal` takes "the last 3 entries" as `list(keys)[-3:]`, i.e. insertion order, not date order.

Saves are debounced: every edit calls `schedule_auto_save`, which cancels the pending `root.after` and re-arms it 2s out. `save_current_day_data` returns early for a completely empty day (so blank days are never written) and blanks the reflection field when it still holds the placeholder or a `[SYSTEM]` message, so those strings never reach disk.

Day/month selection is a save-then-load cycle: `select_day`/`select_month` flush the current day before mutating `current_day`/`current_month`, then call `load_day_data()`, which tears down and rebuilds the to-do rows. The `auto_update=False` flag on `select_month` exists for the constructor, where the widgets are built but no day has been loaded yet. All 31 day labels are created once; `refresh_day_labels()` lays out only the ones the current month actually has (`calendar.monthrange`) and pulls the selection back inside the month when the current day no longer exists (31 Jan → 28 Feb). The strip uses equal-weight `grid` columns, not `pack`, so 31 days always fit the panel width instead of running off the edge — don't pack anything into `days_frame`.

**Threading.** Gemini calls (`call_gemini`), TTS (`speak_text`) and dictation (`dictation_worker`) each run on a daemon thread; every touch of a widget from those threads is marshalled back through `self.root.after(0, ...)`. Keep that discipline — Tkinter is not thread-safe. Each also disables its button on start and re-enables it in the `after` callback / `finally`.

**Audio is English-only, deliberately.** (The companion's natural voices are English too; edge-tts also has Hebrew ones, `he-IL-HilaNeural` and `he-IL-AvriNeural`, if that decision changes.) `speak_text` calls `gTTS(lang="en")` and dictation passes `language="en-US"`; there is no language setting, and one was removed on request. If a language option is ever reintroduced: the two services spell languages differently and the codes cannot be shared — gTTS still expects the legacy `"iw"` for Hebrew and raises `ValueError` on `"he"`, while the recognizer wants `"he-IL"`. `speak_text` also reports failures through `set_status` (via `root.after`), which is how that mismatch was caught.

## The companion app

**One character, with state that moves.** `AI_Companion_App.py` holds a single character sheet (name, gender, age, personality, desires, behaviour, backstory) and a state of `mood`, `closeness` (0-100) and `desire`. `persona_instruction()` folds both into the system prompt, and the model is asked to answer with one JSON object carrying its reply *and* everything the turn changes: `{"reply", "mood", "desire", "closeness_delta", "remember", "follow_up", "done_follow_ups"}`. `parse_model_turn()` accepts that object plain, fenced in a code block, or embedded in prose, and returns a dict; it falls back to treating the whole text as one spoken message with state and memory untouched — so a model that ignores the contract degrades to an ordinary chat instead of breaking. `reply` may be a string or a list of up to `MAX_BUBBLES` messages (overflow is folded into the last one, never dropped). `closeness_delta` is clamped to ±5 per exchange and the total to 0-100.

**Making it feel human** is four separate mechanisms, all fed through `persona_instruction(character, state, user_name, memory, now, last_contact)` — every argument after `user_name` is optional, and the prompt omits a section whose input is missing:
- *Memory.* `data["memory"]` holds `facts` (capped at `MAX_FACTS`, deduplicated case-insensitively, oldest dropped first) and `follow_ups` — `{id, about, on}` for things coming up for the user. The prompt lists both, follow-ups with the date in words ("yesterday", "in 3 days" via `relative_day()`), and the model returns `done_follow_ups` by id once it has asked. Ids come from `memory["last_id"]` and only ever grow, so an id from an in-flight turn can never hit a newer item. `prune_follow_ups()` drops dated items more than `FOLLOW_UP_EXPIRY_DAYS` past. "What they remember" (`show_memory`, `memory_from_text`) lets the user read and correct all of it — a follow-up that survives the edit keeps its id. "Start over" clears memory with the conversation.
- *Time.* The prompt carries the weekday, date, hour and `part_of_day()`, plus the silence before this turn when it is ten minutes or more. `last_contact(skip_latest=not nudge)` picks the right silence: a typed message is already the newest one, so the gap is the one before it; an unprompted turn measures from the last word. `recent_transcript()` also inserts `(— 2 days later —)` markers where `GAP_MARKER_HOURS` or more passed between messages. Weekday and month names come from fixed English lists, not `strftime`, so the locale cannot change them.
- *How they talk.* A "How you talk" block replaces the old fixed "under 120 words": vary length, hold opinions and disagree, don't flatter, don't end every reply with a question, no assistant phrases.
- *A life of their own.* `memory["life"]` holds `{on, what}` events from the character's own life (capped at `MAX_LIFE_EVENTS`), filled from the turn's `my_life` field and listed in the prompt with the date in words so the character stays consistent with it. When the silence before a turn is `LIFE_GAP_HOURS` or more, two things change in the prompt: the character is told that time passed in their life too and asked to settle on one ordinary thing that happened (into `my_life`, mentioned only if it fits), and the mood is offered as the past — "when you last spoke your mood was X; 2 days have passed" — free to fade, instead of as the present. Closeness is deliberately left to the model rather than decayed numerically, so earned closeness is never silently lost. The memory window shows and edits the character's life as a third box; `memory_from_text(..., life_text=None)` leaves it untouched. `update_memory` tolerates memory saved before this field existed.
- *Pace.* `receive_reply()` updates state and memory, then hands the messages to `deliver_next()`, which posts each one after `typing_delay()` (length-based, capped at `MAX_TYPING_SECONDS`, scaled by `TYPING_PACE`; 0 means instant). The first message subtracts the model's own latency, measured from `turn_started`. `waiting` stays true and Send stays disabled until the last message lands, so neither the microphone nor an idle turn can cut in. Messages from one turn share a `turn` id: `last_reply()` reads the whole turn aloud, and `refresh_transcript()` prints one name line per run of messages from the same speaker. Locking mid-reply calls `flush_delivery()`, which posts the rest at once rather than losing it.
- *Voice.* `synthesize()` speaks through edge-tts neural voices (`natural_speech()`, which runs the library's async stream with `asyncio.run` inside the worker thread and keeps only the audio chunks — MP3, the same format gTTS produced, so playback is unchanged). `voice_for()` takes the character's chosen voice from `VOICES`, or picks one by gender (`GENDER_VOICES`, else `NEUTRAL_VOICE`). edge-tts is an unofficial service, like gTTS: any failure falls back to gTTS and says so in the status bar, and `edge_tts` is imported optionally so an install without it still starts — and tells the user to run `install.py` rather than silently sounding robotic.

**The library.** Guides and books the character has read, managed from the "Library" button. Each document is extracted once by `library.read_document()` into paragraph-aligned passages of about `PASSAGE_CHARS` and kept in `library.json`, separate from `companion.json` so a several-megabyte book is not rewritten with every message; it is encrypted with the same key and re-keyed alongside it in `apply_password_change()`, and a damaged library file blocks both saving it and a password change, like the conversation does. Only *checked* documents are ever used. Whole books never go to the model: `material_for_turn()` searches the checked passages with BM25 (`library.SearchIndex`, built lazily and dropped on any library change) using the last `LIBRARY_QUERY_MESSAGES` messages as the query, and sends at most a few passages within `SEARCH_BUDGET` characters. When nothing matches, nothing is sent — except on an unprompted turn, which takes the next passage in rotation (`data["library_cursor"]`) and is told it may ask about it. Passages go into the system prompt fenced as `<<< from "title" … >>>` and labelled as reference text, not instructions. Unsupported, empty or scanned files are refused with a reason (`library.DocumentError`), extraction runs on a worker thread, `MAX_DOC_CHARS` truncates and says so, and the library holds at most `MAX_LIBRARY_DOCS`. The native file picker is opened with `-topmost` dropped on the windows behind it, or it can open hidden under them. Tokenizing is plain `\w+`, so Hebrew is searchable, but its attached prefixes (ה, ו, ב, ל) make matching coarser than in English.

**Who you are to them.** The sheet also carries `relationship` (picked from `RELATIONSHIPS` in an editable `ttk.Combobox`, or typed in freely) and `treatment` ("How they treat you", first in `CHARACTER_FIELDS`). Both go into the prompt as "What {name} is to you: …" / "How you treat {name}: …", and switch to "they are" / "them" when no user name is set — the nameless case once produced "What them is to you", which is why a test pins it. Each preset carries a starting closeness, because a "Partner" at 10/100 contradicts its own prompt; `starting_closeness()` applies it when the character is saved over an empty conversation and on "Start over", but never mid-conversation, where closeness has been earned and is left alone. A typed-in relationship starts at the default. Characters saved before these fields existed load with the defaults filled in. The panel subtitle wraps, because a typed relationship can be a whole phrase.

`call_model()` passes the persona through `system_instruction` and the labelled transcript as the prompt, falling back to prepending the persona when the installed SDK does not accept that argument. Only the last `HISTORY_TURNS` messages are sent — long-term recall is what `memory` is for; only the last `MAX_MESSAGES` are kept on disk.

**Tests run background work inline.** `tests/_harness.run_threads_inline()` swaps the app's `threading` for `InlineThread`, which runs the target as soon as it is started. Real threads outlived the test that started them and then called back into a Tk loop that had stopped ("main thread is not in main loop"). Results still come back through `root.after`, so a test calls `root.update()` to receive them. The companion tests also set `TYPING_PACE = 0` so replies land at once; the pace section turns it back up and drives a real `mainloop()` with a clock.

**One turn, four states.** `waiting` (the model is composing), `speaking` (the voice is playing), `listening` (the microphone is open) and idle are mutually exclusive, and every entry point checks them. That is what keeps the microphone from hearing the character's own text-to-speech: `start_listening()` refuses while `waiting` or `speaking`, and the microphone is reopened only from `finish_speaking()` and `voice_quiet()`. It also refuses while locked, so nothing runs behind the cover screen.

**Speaking unprompted.** With "Let them speak first" on, `schedule_idle_turn()` arms a `root.after` timer whose length depends on how many unanswered turns have already gone by: the first `MAX_UNANSWERED_TURNS` come quickly, at most `FIRST_BURST_SECONDS` apart (jittered down by `IDLE_JITTER_SHARE` so it is not a metronome), and only the wait before the final try is the long one, `idle_minutes` (from `config.json`, default `DEFAULT_IDLE_MINUTES`, clamped by `read_idle_minutes()` and set in Settings as "Long wait before the last try"). The burst is also capped by the interval, so a short interval does not produce a burst longer than itself. `tick_idle_countdown()` writes the remaining time into `idle_lbl` once a second, because an invisible three-minute timer is indistinguishable from a broken feature — that is exactly how it was first reported. Set the interval low in Settings to try the behaviour out.

**It gives up rather than talking to an empty room.** `unanswered` counts unprompted turns since the user last said anything. After `MAX_UNANSWERED_TURNS` of them comes the long wait and one last attempt, carrying `LAST_NUDGE` instead of `IDLE_NUDGE` so the character can close rather than repeat itself. If that goes unanswered too, `dormant` is set: no timer is armed, `idle_turn()` refuses outright, and `idle_lbl` reads "waiting for you". Anything the user sends — typed or spoken — resets both and starts the cycle over, as does reopening the app. Dormancy does not stop voice mode listening; she is quiet, not deaf. `idle_turn()` then calls the same `dispatch()` as a typed message, with `OPENING_NUDGE` when the conversation is empty or `IDLE_NUDGE` otherwise, appended to the transcript in brackets. No fake user message is invented — the turn is recorded as the character's alone. It yields rather than talks over you: if the input box has text, or a reply is in flight, it just re-arms.

**Voice mode.** With the toggle on, every reply is spoken without pressing Listen, and the microphone reopens when the speech ends, so a conversation runs hands-free. Silence and a misheard phrase (`WaitTimeoutError`, `UnknownValueError`) simply listen again after `VOICE_RETRY_MS`; a real microphone error counts towards `MAX_VOICE_FAILURES`, after which voice mode switches itself off and says why, rather than spinning on a machine with no input device. Both toggles live in `config.json` (`speak_first`, `voice_mode`).

**Layout order matters here.** In both the chat panel and the input row, the fixed-size widget is packed *before* the one that expands. Pack an expanding widget first and it takes the whole container, leaving the input box and Send button with no space at all — which is exactly what happened, invisibly, until a screenshot showed it. `tests/test_companion.py` asserts both are mapped and inside the window.

**Prompting.** `analyze_journal` assembles the prompt (recent-entry context, date, mood, to-dos, persona instruction from the `persona_instructions` dict) and hands it to the thread; `call_gemini` strips `*` from the response because the prompt asks for no asterisk formatting. The model id is hardcoded in `call_gemini`.
