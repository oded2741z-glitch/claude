# אינטרקום P2P — מדריך משתמש

מערכת שיחה קולית בין שני מחשבים. אין ממשק גרפי: המערכת רצה ברקע, ונשלטת
דרך קבצי טקסט שכל תוכנה יכולה לכתוב ולקרוא.

---

## 1. איך זה בנוי

| | מחשב A | מחשב B |
|---|---|---|
| מה רץ עליו | שרת ההצמדה **וגם** צד בשיחה | צד בשיחה בלבד |
| ציוד | אוזניות (מיקרופון ורמקול באותו התקן) | רמקולים ומיקרופון נפרדים |
| הקובץ להתקנה | `intercom_A.py` | `intercom_B.py` |

**שרת ההצמדה רק מכיר בין השניים.** הוא מוסר לכל צד את הכתובת של השני, ומאותו
רגע הקול עובר ישירות בין המחשבים ולא דרכו. לכן איכות השיחה לא תלויה בו.

---

## 2. לפני שמתחילים

- **Python 3** מותקן על שני המחשבים. ב-Windows, בהתקנה יש לסמן
  **"Add Python to PATH"** — בלי זה ההתקנה תיכשל.
  (אם השתמשתם בקובץ ה-EXE — ראו סוף סעיף 3 — לא צריך Python בכלל.)
- **חיבור רשת** בין המחשבים. אם הם ברשת מקומית אחת — זה הכל. אם הם מעבר
  לאינטרנט, ראו סעיף 7.
- **הציוד מחובר** לפני ההפעלה. (אפשר גם לחבר אחר כך — המערכת תמתין ותתחבר
  לבד ברגע שהציוד יזוהה.)

---

## 3. התקנה

### Windows

פתחו שורת פקודה **כמנהל** (כדי שגם חוק חומת האש ייווצר), ובתיקיית הפרויקט:

```
cd deploy\windows
```

- על **מחשב A** הריצו: `install.bat A`
- על **מחשב B** הריצו: `install.bat B 192.168.1.10` — כשהמספר הוא הכתובת של מחשב A

ההתקנה מתקינה את הספריות, מעתיקה את הקובץ ל-`C:\intercom`, יוצרת קיצורי
הדלקה וכיבוי, ורושמת משימה שמפעילה את המערכת בכל כניסה למחשב.

לתיקייה אחרת: `install.bat A "" D:\intercom`

### Linux

- על **מחשב A**: `./deploy/linux/install.sh a`
- על **מחשב B**: `./deploy/linux/install.sh b 192.168.1.10` — הכתובת של מחשב A

מתקין כשירות משתמש שעולה עם המחשב.

### התקנה בלי Python — קובץ EXE

אפשר לבנות קובץ הפעלה עצמאי שכולל בתוכו את Python ואת כל הספריות, ואז על
המחשב שמפעיל את המערכת לא צריך להתקין שום דבר.

הבנייה נעשית **פעם אחת**, על מחשב Windows שיש בו Python:

```
cd deploy\windows
build_exe.bat
```

נוצרים `intercom_A.exe` ו-`intercom_B.exe` בתיקיית `dist`. מעתיקים לכל מחשב
את הקובץ שלו, ומריצים שם את `install.bat` כרגיל — הוא מזהה את ה-EXE לבד,
מדלג על כל שלב ההתקנה של Python, ומשתמש בו.

הקובץ רץ בלי חלון. כל מה שהיה מודפס למסך נכתב ל-`node.log` בתיקיית ההתקנה.

### התקנה ידנית (בלי סקריפט)

מעתיקים קובץ אחד בלבד למחשב — `intercom_A.py` או `intercom_B.py` — ומריצים:

```
pip install sounddevice numpy
python intercom_A.py
```

## 4. שימוש יומיומי

בתיקיית ההתקנה נוצרים שלושה קבצים. **אלה כל הממשק של המערכת:**

| הקובץ | למה הוא משמש |
|---|---|
| `switch_A.txt` | הדלקה וכיבוי. מילה אחת בלבד |
| `control_A.txt` | הגדרות — כתובות, פורט, שם |
| `status_A.txt` | המצב הנוכחי. המערכת כותבת, אתם קוראים |

### פתיחה וסגירה של שיחה

ב-Windows — לחיצה כפולה על `on.bat` או `off.bat` בתיקיית ההתקנה. או מכל
תוכנה, כתיבת מילה אחת לקובץ:

| מה כותבים בקובץ | מה קורה |
|---|---|
| `on` | פותח שיחה |
| `off` | סוגר שיחה |
| `quit` | מכבה את המערכת |

השינוי נכנס לתוקף **תוך חצי שנייה**, בלי להפעיל שום דבר מחדש.

### התוכנה `toggle_call.py`

במקום לכתוב לקובץ ידנית, אפשר להשתמש בתוכנית הקטנה שמצורפת. היא הופכת את
המצב, ומחכה עד שהמערכת מאשרת שהיא קלטה:

```
python toggle_call.py
python toggle_call.py off
python toggle_call.py --role B
```

בלי ארגומנט היא מחליפה מצב; עם `on` / `off` / `quit` היא כופה מצב מסוים.

מה שמודפס:

```
switch_A.txt: on -> off
  node confirmed: state = idle
```

### כפתור על המסך — `toggle_gui.py`

מי שמעדיף כפתור על פני שורת פקודה: חלון קטן עם כפתור אחד גדול, ירוק כשהשיחה
פתוחה ואדום כשהיא סגורה. לחיצה מחליפה מצב, ומתחתיו מוצג המצב החי של המערכת —
עם מי מדברים וכמה זמן.

```
python toggle_gui.py
python toggle_gui.py --role B
```

הקובץ `toggle_call.py` חייב להיות באותה תיקייה. שימו לב שזו תוכנת הפעלה
לשולחן העבודה בלבד — **המערכת עצמה ממשיכה לרוץ בלי ממשק גרפי**, והכפתור רק
כותב לאותו קובץ מתג.

היא מחזירה **קוד יציאה 0** רק אחרי שהמערכת אישרה, ו-**1** אם אף אחד לא קלט
את השינוי תוך 5 שניות. כך תוכנה שמפעילה אותה יודעת להבחין בין "הוחלף" לבין
"המערכת לא רצה". להוספת `--no-wait` היא כותבת ויוצאת מיד.

> **שימו לב:** אם אתם עורכים את הקובץ בעורך טקסט, השינוי נכנס לתוקף רק אחרי
> **שמירה**. זה בלתי נמנע — עד שלא שמרתם, הקובץ על הדיסק לא השתנה. תוכנה
> שכותבת את הקובץ בקוד לא מושפעת מזה: אצלה הכתיבה היא השמירה.

## 5. איך יודעים מה קורה — `status_A.txt`

הקובץ מתעדכן כל הזמן. אלה השדות שחשובים:

| שדה | משמעות |
|---|---|
| `updated` | מתי נכתב לאחרונה. **אם הוא לא זז — המערכת לא רצה** |
| `state` | `idle` כבוי · `waiting` מחכה לצד השני · `punching` מתחבר · `live` שיחה פעילה |
| `rx_age` | כמה שניות עברו מאז שהגיע קול. ב-שיחה תקינה זה קרוב ל-0 |
| `peer_id` | עם מי מדברים |
| `signalling` | `up` = שרת ההצמדה פעיל (רק במחשב A) |
| `remote_ready` | `yes` = הצד השני מחובר ומוכן (רק במחשב A) |
| `call_seconds` | כמה זמן השיחה נמשכת |

**סדר הבדיקה כשמשהו לא עובד.** עברו עליהם לפי הסדר; העצירה הראשונה
היא הבעיה:

1. `updated` זז?
2. `signalling` שווה ל-`up`?
3. `remote_ready` שווה ל-`yes`?
4. `state` שווה ל-`live`?
5. `rx_age` קרוב ל-0?

## 6. פתרון תקלות

| מה רואים | מה זה אומר | מה עושים |
|---|---|---|
| `updated` לא זז | המערכת לא רצה, או רצה בתיקייה אחרת | הפעילו את `run.bat`. בדקו את `node.log` |
| בלוג: `Waiting for audio devices` | האוזניות/הרמקולים לא מזוהים | חברו את הציוד. המערכת תתחבר לבד |
| `signalling = up` אבל `remote_ready = no` | מחשב B לא מגיע לשרת | חומת אש, או `server_ip` שגוי אצל B |
| `remote_ready = yes` אבל נשאר `waiting` | הצד השני לא פתח שיחה | `on` גם בצד השני |
| `state = live` אבל אין קול | ראו למטה — כמעט תמיד NAT או שירות | סעיף 7, וההערה על שירותים |
| `rx_age` גדל | הקול מהצד השני נפסק | המערכת תתאושש לבד תוך 3 שניות |
| `signalling = error` בקובץ הסטטוס | הפורט תפוס — בדרך כלל עותק שני של המערכת שעדיין רץ | `signalling_error` באותו קובץ אומר בדיוק מה קרה. סגרו את העותק הישן, או שנו `port` |
| בלוג: `WARNING: registering over 127.0.0.1` | מחשב A נרשם לעצמו דרך כתובת פנימית | תקנו `server_ip` ב-`control_A.txt` לכתובת ה-LAN האמיתית |

### שתי מלכודות שחוזרות

**תיקיית העבודה.** הקבצים נוצרים בתיקייה שממנה המערכת רצה, לא ליד קובץ
ה-Python. אם הפעלתם ממקום אחר, נוצר סט קבצים חדש — ואתם כותבים לקובץ שאף
אחד לא קורא. הסקריפטים כאן מטפלים בזה; בהפעלה ידנית, היכנסו לתיקייה קודם.

**שירות Windows.** אם מישהו יתקין את זה כשירות אמיתי (NSSM / `sc create`),
הכל יעבוד חוץ מהקול. שירות רץ מחוץ ל-session של המשתמש ואין לו גישה לכרטיס
הקול. ההתקנה כאן משתמשת במתזמן המשימות בכוונה, כדי להימנע מזה.

## 7. שני המחשבים לא באותה רשת

בתוך רשת מקומית אחת אין מה להגדיר. אם המחשבים מעבר לאינטרנט:

**ב-`control_A.txt`** (מחשב A):
```
local_mode = off
ext_ip     = 203.0.113.45
server_ip  = 192.168.1.10
```

- `ext_ip` — הכתובת הציבורית של הראוטר של מחשב A.
- `server_ip` — כתובת ה-LAN של מחשב A. **לא** הציבורית.

**ב-`control_B.txt`** (מחשב B):
```
server_ip = 203.0.113.45
```

- כאן דווקא כן הכתובת הציבורית של מחשב A.

**בראוטר של A:** ניתוב פורט (port forward) של **UDP 9999** לכתובת ה-LAN של A.

אם אחרי כל זה מגיעים ל-`state = live` בלי קול — סוג ה-NAT של הספק לא מאפשר
חיבור ישיר (Symmetric NAT). הפתרון הפשוט הוא VPN בין המחשבים (WireGuard או
Tailscale), ואז חוזרים ל-`local_mode = on` עם כתובות ה-VPN.

## 8. שאלות שחוזרות

**אפשר לשנות הגדרות בזמן שהמערכת רצה?** כן. כל שינוי ב-`control` נקלט תוך
חצי שנייה. שינוי פורט מאתחל את השרת לבד.

**מה קורה אם שולפים את האוזניות באמצע שיחה?** השיחה נסגרת, והמערכת חוזרת
להמתין. ברגע שהאוזניות חוזרות היא מתחברת מחדש לבד. לא צריך לגעת בכלום.

**מה קורה אם המחשב השני נכבה?** אחרי 3 שניות בלי קול השיחה נסגרת, ושני
הצדדים חוזרים להמתין. כשהוא חוזר, השיחה נפתחת מחדש אוטומטית.

**המערכת עולה לבד אחרי הפעלה מחדש?** כן, בכניסה למשתמש. אם המחשב צריך לעלות
בלי שאף אחד מתחבר, הגדירו כניסה אוטומטית (autologon) למשתמש ייעודי.

**איפה הלוג?** `node.log` בתיקיית ההתקנה (Windows), או
`journalctl --user -u intercom-a -f` (Linux).
