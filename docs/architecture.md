# ארכיטקטורת המערכת

## מטרה
לשחזר את התנהגות ה"רחפן שעוקב אחרי אדם" מהסרטון הישן, אבל עם רחפן **קטן, זול
ובר-בנייה** שבו ה-Raspberry Pi מבצע את כל הבינה (זיהוי + מעקב), ובקר טיסה ייעודי
מבצע את הייצוב והתעופה בפועל.

## עיקרון מנחה: הפרדת אחריות
אל תריצו את לולאת הייצוב של הרחפן (stabilization, ~1000Hz) על ה-Pi. זה מסוכן ולא
אמין. במקום זה:

- **בקר טיסה (Flight Controller)** – שבב ייעודי (למשל בקר שמריץ ArduPilot/PX4).
  אחראי על ייצוב, החזקת גובה, failsafe. עובד גם אם ה-Pi קרס.
- **מחשב נלווה (Companion) = Raspberry Pi** – "המוח". רואה, מזהה, מחליט לאן לזוז,
  ושולח **פקודות מהירות ברמה גבוהה** לבקר הטיסה. זה נקרא ארכיטקטורת
  *offboard / guided control*.

```
┌──────────────────────────────────────────────┐
│                 Raspberry Pi                    │
│  ┌────────┐   ┌──────────┐   ┌──────────────┐  │
│  │ מצלמה  │──▶│  זיהוי   │──▶│   בקרי PID   │  │
│  │ Camera │   │  אדם     │   │  + follower  │  │
│  └────────┘   └──────────┘   └──────┬───────┘  │
└─────────────────────────────────────┼──────────┘
                                       │ MAVLink (UART/USB)
                                       ▼
                          ┌────────────────────────┐
                          │   בקר טיסה (ArduPilot) │
                          │  ייצוב, גובה, failsafe │
                          └───────────┬────────────┘
                                      ▼
                          ┌────────────────────────┐
                          │  ESC + 4 מנועים        │
                          └────────────────────────┘
```

## צינור העיבוד (Pipeline)

### 1. קלט וידאו
מצלמת Pi Camera (CSI) או מצלמת USB. רזולוציית עבודה מומלצת: 320×240 או 416×416,
כדי לשמור על קצב פריימים סביר על ה-Pi.

### 2. זיהוי ומעקב אדם (`src/vision/detector.py`)
שתי שכבות:
- **Detector** – מוצא אדם בפריים. אפשרויות לפי כוח החישוב:
  - `MobileNet-SSD` דרך OpenCV DNN – קל, רץ על Pi 4 / Pi Zero 2 W בכ-5-15 FPS.
  - `YOLOv8-nano` – מדויק יותר, מומלץ עם מאיץ (Coral USB / Hailo).
  - במצב פיתוח: HOG people detector של OpenCV (ללא מודל חיצוני, לבדיקות).
- **Tracker** – אחרי זיהוי ראשוני, עוקב אחרי אותו אדם בין פריימים (CSRT/KCF).
  זה חוסך חישוב וגם "נועל" על אדם ספציפי במקום לקפוץ בין אנשים.

הפלט: `BoundingBox(cx, cy, w, h, confidence)` בקואורדינטות מנורמלות [0,1].

### 3. חישוב שגיאות בקרה (`src/control/follower.py`)
מהתיבה מחשבים שלוש שגיאות מול "יעד":
- **yaw error** = `cx - 0.5` → סטייה אופקית. חיובי = האדם מימין → סובב ימינה.
- **distance error** = `target_height - bbox_height` → גודל התיבה מייצג מרחק.
  תיבה קטנה מדי = האדם רחוק → טוס קדימה. גדולה מדי = קרוב → אחורה.
- **altitude/vertical error** = `cy - target_cy` → שמירת האדם במרכז אנכי.

### 4. בקרי PID (`src/control/pid.py`)
כל שגיאה עוברת בקר PID נפרד שמייצר פקודה חלקה (מונע תנודות/oscillation):
- `yaw_pid` → קצב סיבוב (rad/s)
- `forward_pid` → מהירות קדימה/אחורה (m/s)
- `vertical_pid` → מהירות אנכית (m/s)

הפקודות מוגבלות (clamp) למהירויות מקסימום נמוכות ובטוחות.

### 5. שליחה לבקר הטיסה (`src/drone/*.py`)
- **MAVLink** (`mavlink_drone.py`): שולח `SET_POSITION_TARGET_LOCAL_NED` עם וקטור
  מהירות ב-body frame + yaw rate, כשהרחפן במצב `GUIDED`. דורש `pymavlink`.
- **Tello** (`tello_drone.py`): שולח פקודות `rc a b c d` דרך ה-SDK. הכי פשוט.
- **Sim** (`sim_drone.py`): לא שולח כלום, רק מדפיס/מצייר את הפקודות. לבדיקות.

## מצבי בטיחות (State Machine)
```
DISARMED ──arm──▶ SEARCHING ──found person──▶ FOLLOWING
   ▲                  ▲                            │
   │                  └────lost person (timeout)───┘
   └──────────── kill / RC override / failsafe ─────────┘
```
- **SEARCHING**: לא רואים אדם → hover במקום (מהירות אפס), אולי סיבוב איטי לחיפוש.
- **FOLLOWING**: יש נעילה → בקרה פעילה.
- **איבוד מטרה**: אם אין זיהוי מעל `lost_timeout` שניות → עצור וחזור ל-SEARCHING.
- **kill switch**: מתג RC ידני שתמיד גובר על ה-Pi (RC override) → hover/land מיידי.

## ביצועים ומגבלות
- Pi Zero 2 W: מספיק ל-MobileNet-SSD ב-320px, ~8-12 FPS. גבול לזיהוי מהיר.
- Pi 4/5: נוח יותר, אפשר YOLO-nano.
- מאיץ (Google Coral USB / Hailo-8L): קופץ ל-30+ FPS, מומלץ למעקב אמין בתנועה.
- זמן חביון (latency) הוא האויב: פריים איטי → הרחפן מגיב מאוחר → תנודות. שמרו על
  קצב פריימים גבוה ומהירויות נמוכות.
